# Запуск окружения с использованием внешних сервисов

⚠️ пример не запускается тк vedro не поддерживает инстанцирование паралельных тестов + нужна поддержка параллелизма в менеджере окружения

При запуске с параллельных потоков на все запускаются единственные копии сервисов `kafka` и `postgres_db` в остальных сервисах подмениться ENV и конфиги для использования внешнего сервиса и учетом уникального id потока сервиса

**При подмене сервисов нужно параметризовать**
- ENV для приложения
- конфиг файлы приложения (⚠ нет реализации)
- ENV для тестов
- шаги миграций и предустановок
- контексты тестов/интерфейсов взаимодействия с подмененными сервисами

По количеству разных окружений из тестов `EnvDisabledFeatureEnvironment` и `EnvDisabledFeatureEnvironment` будут организованы паралельные окружения (контуры):
- app_HIHW
- migrations_HIHW

и
- app_SFEA
- migrations_SFEA

где `HIHW` - рандомный хеш для окружения `EnvDisabledFeatureEnvironment` и `SFEA` - рандомный хеш для окружения `EnvDisabledFeatureEnvironment`

и общими postgres_db и kafka (⚠️из опасного - все сервисы неизолировано доступны в обоих контурах, можно конечно подумать про разделение по compose_project + прокси в другой project для шаринга тяжелых сервисов-синглтонов).

каждый паралельный поток помигрирует свою базу данных `app_db_adwq` и `app_db_cdsd` в рамках инстанса postgres_db (тк ведро выдаст каждому потоку свой worker_id) 
соответствующие различные параметры DSN_ВИ получат остальные сервисы в том числе и миграции контуров `migrations_HIHW`, `migrations_SFEA`
а так же разойдутся по топикам кафки за счет `worker_instance(name)` дописывающего worker_id от ведра.

## Запуск
### Подтянуть актуальные образы из CI и поднять bootsrap
```shell
docker-compose pull | true
docker-compose down
docker-compose up -d dockersock maxwelld e2e
```

### ⏩ Запустить тесты использую переопределенные параметры сервиса

```shell
docker-compose exec e2e python3 -m vedro run --x-parallelism=2
```


# Идея по реализации паралелизма в ведре 

1. Инстанцировать N серверов - подпроцессов ведра с набором разбитых тестов.
2. По каналу отправить им команду стартовать
3. В основном (исходном) инстансе по каналу собирать результаты/stdout и выводить их
4. в основном (исходном) инстансе мержить итоговый отчет [и обрабатывать прочие события завершения теста секций] и результатов (?)
